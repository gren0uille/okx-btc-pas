# Прогноз объёма и волатильности BTC/USDT на OKX

Учебная система по предметной области № 21 «Рынок цифровых активов». После завершения суток UTC она должна прогнозировать объём торгов BTC/USDT на OKX и однодневную оценку волатильности следующего дня. Второй источник — официальный курс USD/RUB Банка России.

Сейчас завершены постановка задачи и загрузчики исходных данных. `clean`, `mart`, модели и дашборды ещё не сделаны. Предметная область и зарубежный источник требуют согласования с преподавателем.

## Почему эти источники

- OKX даёт историю дневных свечей BTC/USDT в JSON: цену и объём конкретной площадки. При проверке 19 сентября 2026 года API вернул 3 173 завершённых дня с 11 января 2018 года по 18 сентября 2026 года.
- Банк России даёт USD/RUB в XML. Курс используется как возможный внешний признак, а не как доказанно полезная причина движения крипторынка. Выходные и разницу между USD и USDT необходимо учитывать.

Методика определения двух целей и границы результата изложены в [docs/01_problem_statement.md](docs/01_problem_statement.md).

## Установка и проверка

```bash
python -m pip install -e '.[dev]'
python -m okx_btc_pas.source_probe --days 30
pytest
```

Публичные маршруты не требуют торгового аккаунта или ключа API. Проверка TLS в рабочем коде включена. Флаг `--insecure` предусмотрен только для разовой диагностики в среде с доверенным прокси и не должен использоваться при обычной загрузке.

## Практическая работа 2

Создайте `.env` по образцу `.env.example` и задайте пароль PostgreSQL. Затем запустите:

```bash
docker compose run --build --rm loader
docker compose run --rm loader
```

Загрузчик создаст схемы и таблицы, запросит историю OKX постранично и курс ЦБ по годовым окнам. При следующем запуске он начнёт с даты после последней сохранённой. Завершённость свечи проверяется по `confirm=1`; текущий незавершённый день не сохраняется и будет запрошен снова. Уникальный ключ предотвращает повторную запись, `load_log` хранит статус, количество полученных и добавленных строк, последнюю дату и ошибку. При ошибке транзакция загрузки откатывается.

Проверить результаты:

```bash
docker compose exec db psql -U pas_user -d pas -c 'SELECT source, status, rows_received, rows_added, last_loaded_date FROM load_log ORDER BY id;'
docker compose exec db psql -U pas_user -d pas -c 'SELECT count(*) FROM raw.okx_btc_usdt_daily;'
docker compose exec db psql -U pas_user -d pas -c 'SELECT count(*) FROM raw.cbr_usd_rub;'
```

Локально можно задать `DATABASE_URL` и вызвать `python -m okx_btc_pas.ingestion`. Для тестов допустима SQLite с заменой схемы `raw`; контейнерный запуск PostgreSQL в среде подготовки отчёта не проверялся из-за отсутствия Docker.

## Структура

```text
okx-btc-pas/
├── docs/01_problem_statement.md
├── scripts/build_report.py
├── src/okx_btc_pas/source_probe.py

├── tests/
├── .env.example
├── Dockerfile
├── compose.yaml
├── pyproject.toml
└── README.md
```

`scripts/build_report.py` собирает накапливаемый DOCX из образца титульного листа. Новые практики добавляются в этот скрипт; расположение исходного DOCX и путь результата задаются параметрами. После изменения отчёт необходимо заново отрендерить и проверить постранично.

Для повторной сборки в этой рабочей среде:

```bash
/Users/timurkamalov/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 scripts/build_report.py
```

Скрипту нужны `python-docx`, `pypdf` и LibreOffice, используемый средством визуальной проверки. Параметры `--template`, `--output`, `--group`, `--teacher` и `--renderer` позволяют обновить исходный титульный лист, итоговый путь, незаполненные данные и путь рендерера без правки кода. Содержание отчёта хранится в списке `CONTENT`, а страницы содержания вычисляются при предварительном рендере.
