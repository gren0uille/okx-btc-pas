# Прогноз объёма и волатильности BTC/USDT на OKX

Учебный проект по дисциплине «Прогнозно-аналитические системы».
Предметная область № 21 «Рынок цифровых активов».

Система должна после завершения суток по UTC прогнозировать на следующие сутки
два показателя спотовой пары BTC/USDT на бирже OKX:

1. объём торгов в BTC;
2. дневную оценку волатильности по максимуму и минимуму цены (оценка Паркинсона).

**Текущее состояние: система прогноз ещё не выдаёт.** Сделаны постановка задачи
и загрузка исходных данных. Обработка, модели и дашборд — впереди.

---

## Как здесь всё устроено

Данные идут по конвейеру из трёх слоёв. Это стандартная схема в аналитике:
сырое отдельно, очищенное отдельно, готовое к анализу отдельно.

```
Источники                 Слои в базе данных              Результат
─────────                 ──────────────────              ─────────
OKX (JSON)      ──┐
                  ├──►  raw     сырые записи как есть   ──►  clean   ──►  mart   ──►  модель  ──►  дашборд
Банк России (XML) ─┘     + load_log (журнал запусков)      проверено    признаки     прогноз    показ
                         ✅ готово                          ⬜ нет       ⬜ нет       ⬜ нет     ⬜ нет
```

Зачем разделять слои: если модель выдаст странный результат, нужно понимать,
виноваты данные или алгоритм. Сохранённый `raw` позволяет вернуться к исходнику
и перепроверить, ничего не загружая заново.

### Что уже работает

| Слой | Что делает | Статус |
|---|---|---|
| `raw.okx_btc_usdt_daily` | Одна завершённая дневная свеча на дату: цены, объём, исходный JSON | Готово |
| `raw.cbr_usd_rub` | Официальный курс USD/RUB с исходным XML | Готово |
| `load_log` | Журнал: когда запускали, сколько строк получено и добавлено, ошибки | Готово |
| `clean` | Типизация, проверки диапазонов, пропусков, дат | Не начато |
| `mart` | Одна строка на сутки: признаки и целевые значения | Не начато |
| Модели, дашборд | Прогноз и его показ | Не начато |

### Два важных правила, заложенных в код

**Берём только завершённые сутки.** У свечи OKX есть поле `confirm`. Пока сутки
не закончились, оно равно `0`, и такая свеча не сохраняется — иначе в данные
попал бы неполный день и испортил статистику. Незавершённый день будет
загружен позже, когда закроется.

**Не заглядываем в будущее.** Прогнозируя день `d+1`, разрешено использовать
только данные по день `d` включительно. Это главная ловушка прогнозирования:
если случайно подмешать данные прогнозируемого дня, модель покажет блестящую
точность на проверке и провалится в реальности.

## Запуск: пошагово

### Шаг 0. Открыть правильную папку

В VS Code открывайте **папку `okx-btc-pas`**, а не `ПАС`. Проверка: в корне
дерева файлов слева должен быть виден `pyproject.toml`.

Дальше везде открываем встроенный терминал: **Terminal → New Terminal**
(или `Ctrl + ~`). Все команды выполняются в нём.

### Шаг 1. Виртуальное окружение

Виртуальное окружение — это отдельная папка `.venv` с Python и библиотеками
именно этого проекта. Нужна, чтобы библиотеки проектов не конфликтовали
между собой.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,report]'
```

После `activate` в начале строки терминала появится `(.venv)` — признак, что
окружение активно. В новом терминале `activate` нужно повторять.

Скажите VS Code использовать это окружение: `Cmd + Shift + P` →
`Python: Select Interpreter` → выберите вариант с `.venv`. Тогда редактор
перестанет подчёркивать импорты красным.

### Шаг 2. Проверить, что всё цело

```bash
pytest
```

Ожидаемый результат: `6 passed`. Тесты работают на временной базе в памяти
и в интернет не ходят — это быстрая проверка, что код не сломан.

### Шаг 3. Посмотреть на источники живьём

```bash
python -m okx_btc_pas.source_probe --days 30
```

Выведет JSON: сколько свечей вернул OKX, какие у них поля, сколько записей
курса дал Банк России. Ключ или аккаунт не нужны — источники публичные.
Это диагностика, в базу ничего не пишется.

### Шаг 4. Загрузить данные в базу

Здесь нужен **Docker Desktop** — он поднимает PostgreSQL в контейнере, чтобы
не устанавливать базу в систему вручную.

```bash
cp .env.example .env
```

Откройте `.env` и замените `укажите_свой_пароль` на любой свой пароль
(в двух местах). Файл `.env` в git не попадает.

```bash
docker compose run --build --rm loader   # первая загрузка, займёт время
docker compose run --rm loader           # повторный запуск
```

Первый запуск создаёт таблицы и выкачивает историю с 2018 года. Второй —
проверка инкрементальности: он должен добавить `0` новых строк, потому что всё
уже загружено. Это и есть защита от дублей.

Посмотреть результат:

```bash
docker compose exec db psql -U pas_user -d pas -c \
  'SELECT source, status, rows_received, rows_added, last_loaded_date FROM load_log ORDER BY id;'
docker compose exec db psql -U pas_user -d pas -c 'SELECT count(*) FROM raw.okx_btc_usdt_daily;'
docker compose exec db psql -U pas_user -d pas -c 'SELECT count(*) FROM raw.cbr_usd_rub;'
```

Выключить базу, когда закончили: `docker compose down`
(данные сохранятся; `docker compose down -v` сотрёт и их).

## Пересборка отчёта

Текст отчёта хранится в списке `CONTENT` внутри `scripts/build_report.py`.
Новые практические работы дописываются туда, после чего:

```bash
python scripts/build_report.py
```

Скрипт собирает единый DOCX: титульный лист берётся из `assets/title_template.docx`,
содержание нумеруется автоматически.

Для автоматических номеров страниц нужен установленный
[LibreOffice](https://ru.libreoffice.org/) — скрипт использует его, чтобы
измерить реальные страницы. Без него документ всё равно соберётся, но номера
в содержании придётся обновить в Word вручную.

Параметры: `--template`, `--output`, `--group`, `--teacher`, `--renderer`.
Группа и ФИО преподавателя пока не заполнены и задаются этими ключами.

## Про источники и честность результата

**OKX** — публичный JSON API дневных свечей. При проверке 19 сентября 2026 года
он вернул 3 173 завершённых дня с 11 января 2018 года. Длинная история важна:
она позволит обучить модель на ранних датах и проверить на поздних. Но сама по
себе длина истории точность не гарантирует.

**Банк России** — курс USD/RUB в XML (код R01235). Это второй источник, другой
по формату и происхождению. Он рассматривается как *возможный* внешний признак:
поможет ли он прогнозу, покажет только эксперимент. Важные оговорки: USDT не
равен официальному доллару, а курс ЦБ публикуется не каждый календарный день,
тогда как крипторынок торгует ежедневно.

Проверка TLS-сертификатов в рабочем коде **включена**. Флаг `--insecure` есть
только у диагностики `source_probe` и предназначен для разовой проверки в сети
с учебным прокси. В обычной загрузке он не используется.

**Что ещё не подтверждено:** запуск с реальной PostgreSQL через Docker не
проверялся. Точность прогноза не измерена — моделей пока нет. Использование
зарубежного источника требует согласования с преподавателем.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `command not found: python` | Используйте `python3`, либо активируйте `.venv` |
| VS Code подчёркивает импорты | Выберите интерпретатор `.venv` (шаг 1) |
| `docker: command not found` | Docker Desktop не установлен или не запущен |
| `POSTGRES_PASSWORD` ошибка | Не создан `.env` или в нём не заменён пароль |
| Отчёт собрался без номеров страниц | Не установлен LibreOffice — обновите содержание в Word |
