# Постановка задачи системы для BTC/USDT на OKX

## Предметная область и пользователь

Работа относится к предметной области № 21 «Рынок цифровых активов». Объект — спотовая пара BTC/USDT на одной площадке OKX, а не весь мировой рынок биткоина. Пользователь — начинающий аналитик или наблюдающий за рынком частный инвестор. Система помогает заметить ожидаемую необычную активность и ценовые колебания следующего дня; она не выдаёт торговых рекомендаций.

## Два показателя и момент прогноза

После окончания суток `d` по UTC система прогнозирует на следующие сутки `d+1`:

1. `volume_btc` — объём спотовых торгов BTC/USDT на OKX в BTC за сутки UTC. Это поле `vol` завершённой дневной свечи.
2. `volatility_pk` — однодневную оценку волатильности по максимуму и минимуму завершённой свечи: `abs(ln(high/low)) / (2 * sqrt(ln(2)))`. Показатель безразмерный; это оценка по ценовому диапазону, а не десятидневное скользящее среднее и не гарантированный будущий диапазон.

Для строки прогноза `d+1` допустимы только значения завершённых дней по `d` включительно. Фактические `high`, `low` и `vol` дня `d+1` появляются лишь после его окончания. Разбиение для проверки моделей выполняется по времени.

## Источники

### OKX

Публичный API `GET https://www.okx.com/api/v5/market/history-candles` с параметрами `instId=BTC-USDT` и `bar=1Dutc` отдаёт JSON-массив `[ts,o,h,l,c,vol,volCcy,volCcyQuote,confirm]`. `ts` — начало суток UTC; `vol` — количество BTC, `volCcyQuote` — оборот в USDT. `confirm=1` означает завершённую свечу. Получение страниц идёт назад по параметру `after`.

Контрольный запрос 19 сентября 2026 года вернул 3 174 разные календарные даты с 11 января 2018 года по 19 сентября 2026 года, без пропусков в этом интервале. Последняя свеча имела `confirm=0`, поэтому для загрузки и анализа пригодны 3 173 завершённые даты по 18 сентября включительно. Биржа предупреждает, что самая ранняя свеча может быть неполной; её качество предстоит проверить на этапе `clean`.

### Банк России

Публичный XML-сервис `https://www.cbr.ru/scripts/XML_dynamic.asp` с `VAL_NM_RQ=R01235` отдаёт официальный курс USD/RUB и дату действия. Это второй, разнородный по формату источник. Курс — внешний контекст, полезность которого для прогноза BTC/USDT нужно проверять экспериментально. USDT не равен официальному USD, поэтому курс ЦБ не используется для безусловного пересчёта цены BTC/USDT в рубли.

Крипторынок работает ежедневно, а курс ЦБ публикуется не на каждый календарный день. В будущей витрине выбирается последний курс, дата которого не позже дня `d`, то есть дня, данные которого уже известны при прогнозе `d+1`. Возраст курса и перенос через выходные отмечаются отдельно. Курс дня `d+1` в признаки не попадает.

## Слои данных

- `raw.okx_btc_usdt_daily`: одна завершённая дневная свеча на инструмент и дату, исходный JSON и выделенные поля.
- `raw.cbr_usd_rub`: запись курса с исходным XML.
- `clean`: типизация, проверки диапазона цен и объёма, пропусков, дат и соответствия курсу. Этот слой ещё не реализован.
- `mart.daily_market_mart`: одна строка на сутки UTC с признаками и целями. Этот слой ещё не реализован.
- `load_log`: отдельная запись о каждом запуске источника.
- `data_quality_log`, `instrument_history`, `forecasts`: запланированы для последующих этапов, но пока не представлены как реализованные.

## Ограничения

Длинная история позволяет честнее сравнивать модели, но не гарантирует точный прогноз на волатильном рынке. Объём отражает только OKX. У USD/RUB может не оказаться дополнительной прогностической силы. Ранние свечи и резкие режимные изменения следует проверить до обучения. Тема и зарубежный источник должны быть согласованы с преподавателем.

## Завершение первых двух практик

Практика 1 — формулировка задачи, проверка схем источников и длины истории. Практика 2 — автоматическое получение, инкрементальная запись только новых завершённых дат, отсутствие дублей при повторе, повтор сетевых запросов и журнал запусков. Модели, дашборды и слои `clean`/`mart` к этим практикам не относятся.
