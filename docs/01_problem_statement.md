# Постановка задачи

Проект по дисциплине «Прогнозно-аналитические системы».
Предметная область № 21 «Рынок цифровых активов».
Профиль подготовки «Управление данными».

## 1. Объект исследования

Объектом исследования является спотовая торговая пара BTC/USDT на криптовалютной
бирже OKX. Рассматривается торговая активность одной площадки, а не совокупный
оборот мирового рынка биткоина: такое ограничение обеспечивает измеримость и
проверяемость показателей по данным самой биржи.

Выбор инструмента обусловлен требованием к достаточному объёму исторических
данных для проведения временной валидации моделей. Ранее рассматривавшийся
фьючерсный контракт располагал 212 различными торговыми днями, что недостаточно
для разделения выборки на обучающую и контрольную части. Спотовая пара BTC/USDT
имеет непрерывный суточный ряд наблюдений с 11 января 2018 года.

## 2. Пользователь и практическая задача

Пользователем системы является аналитик рынка цифровых активов либо частный
инвестор, наблюдающий за инструментом. Система предназначена для предварительной
оценки ожидаемой торговой активности и ценовой нестабильности на предстоящие
сутки.

Результат работы системы не является инвестиционной рекомендацией. Система не
прогнозирует направление движения цены и не гарантирует доходность операций.

## 3. Прогнозируемые показатели

После завершения суток `d` по всемирному координированному времени система
формирует прогноз на последующие сутки `d+1` по двум показателям.

| Показатель | Определение | Единица измерения |
|---|---|---|
| `volume_btc` | Объём спотовых торгов за сутки, поле `vol` завершённой суточной свечи | BTC |
| `volatility_pk` | Оценка волатильности Паркинсона по экстремумам цены суток | Безразмерная величина |

Оценка волатильности вычисляется по формуле:

```
volatility_pk = |ln(high / low)| / (2 · √(ln 2))
```

Показатель рассчитывается по максимальной и минимальной цене одних суток.
Скользящие оценки за период не применяются: перекрытие соседних окон приводит к
завышенной оценке качества прогноза вследствие сглаженности целевого ряда.

Горизонт прогнозирования составляет одни сутки. При формировании прогноза на
сутки `d+1` допускается использование исключительно данных, доступных по
состоянию на конец суток `d`. Разделение выборки на обучающую и контрольную
части выполняется по времени.

## 4. Источники данных

В соответствии с требованиями методических указаний используются два разнородных
источника, различающихся форматом представления и способом получения данных.

### 4.1. Биржа OKX

Публичный программный интерфейс исторических свечей:

```
GET https://www.okx.com/api/v5/market/history-candles
    instId=BTC-USDT
    bar=1Dutc
```

Формат ответа — массив JSON вида `[ts, o, h, l, c, vol, volCcy, volCcyQuote,
confirm]`, где `ts` — начало суток в миллисекундах, `vol` — объём в базовой
валюте, `volCcyQuote` — оборот в котируемой валюте, `confirm` — признак
завершённости свечи. Постраничное получение данных выполняется в обратном
хронологическом порядке посредством параметра `after`.

В систему принимаются исключительно свечи с признаком `confirm = 1`.
Незавершённая свеча текущих суток содержит неполные данные и подлежит повторному
запросу после закрытия периода.

Авторизация и торговый счёт для доступа к интерфейсу не требуются.

### 4.2. Банк России

Публичный сервис официальных курсов валют в формате XML:

```
GET https://www.cbr.ru/scripts/XML_dynamic.asp
    VAL_NM_RQ=R01235
```

Источник предоставляет официальный курс доллара США к рублю с указанием даты
действия и номинала. Курс рассматривается как внешний фактор, прогностическая
значимость которого подлежит экспериментальной проверке при сравнении моделей.

Учитываются следующие особенности источника. Тезер (USDT) не является
официальной валютой США, вследствие чего курс Банка России не применяется для
пересчёта котировок BTC/USDT в рубли. Биржевые торги ведутся ежедневно, тогда
как официальный курс публикуется не на каждую календарную дату; в витрине
используется последний курс с датой не позднее суток `d`, а давность записи
фиксируется в отдельном атрибуте.

## 5. Архитектура хранения данных

Обработка данных организована в виде трёх слоёв хранения с разграниченной
ответственностью.

| Слой | Ответственность | Объекты |
|---|---|---|
| `raw` | Сохранение полученных данных без преобразований | `okx_btc_usdt_daily`, `cbr_usd_rub` |
| `clean` | Проверка качества и приведение типов | `okx_btc_usdt_daily`, `cbr_usd_rub` |
| `mart` | Формирование аналитической витрины | `daily_market_mart` |

Совместно с разобранными полями в слое `raw` сохраняются исходные фрагменты
JSON и XML, что обеспечивает прослеживаемость происхождения каждого значения до
данных источника.

Выполнение операций фиксируется в журналах: `load_log` содержит сведения о
каждом запуске загрузки, `data_quality_log` — результаты проверок качества с
указанием причин отклонения записей.

Витрина `mart.daily_market_mart` имеет гранулярность одни сутки. Строка содержит
признаки, известные на момент завершения суток `d`, и целевые значения,
относящиеся к суткам `d+1`. Целевые значения хранятся в отдельных атрибутах и в
качестве признаков не используются.

## 6. Ограничения

1. Показатель объёма характеризует торговую активность биржи OKX и не отражает
   оборот прочих торговых площадок.
2. Протяжённость исторического ряда обеспечивает возможность корректной
   временной валидации, однако не гарантирует достижения заданной точности
   прогноза в условиях изменения рыночного режима.
3. Прогностическая значимость курса USD/RUB не установлена и подлежит
   экспериментальной проверке.
4. Достоверность наиболее ранних свечей требует подтверждения: биржа допускает
   неполноту первой записи исторического ряда.
5. Использование источника данных иностранной юрисдикции подлежит согласованию
   с преподавателем.
