# Постановка задачи

Предметная область № 21 «Рынок цифровых активов».

## Объект

Спотовая пара BTC/USDT на бирже OKX. Рассматривается активность одной площадки,
а не всего рынка биткоина.

## Пользователь

Аналитик рынка цифровых активов. Система даёт оценку ожидаемой торговой
активности и нестабильности цены на следующие сутки. Инвестиционной
рекомендацией результат не является.

## Показатели

После закрытия суток `d` по UTC прогнозируются два показателя суток `d+1`:

| Показатель | Определение | Единица |
|---|---|---|
| `volume_btc` | Объём торгов, поле `vol` суточной свечи | BTC |
| `volatility_pk` | Волатильность Паркинсона | Безразмерная |

```
volatility_pk = |ln(high / low)| / (2 · sqrt(ln 2))
```

Волатильность считается по экстремумам одних суток. Горизонт — одни сутки.
В признаки строки `d+1` попадают только данные, известные на конец суток `d`.
Выборка делится на обучающую и контрольную части по времени.

## Источники

### OKX

```
GET https://www.okx.com/api/v5/market/history-candles
    instId=BTC-USDT
    bar=1Dutc
```

Ответ — массив JSON `[ts, o, h, l, c, vol, volCcy, volCcyQuote, confirm]`.
Поле `ts` — начало суток в миллисекундах, `vol` — объём в BTC, `confirm` —
признак завершённости. Постраничная выборка идёт назад по параметру `after`.

Принимаются только свечи с `confirm = 1`. Незавершённая свеча текущих суток
запрашивается повторно после закрытия периода. Авторизация не требуется.

### Банк России

```
GET https://www.cbr.ru/scripts/XML_dynamic.asp
    VAL_NM_RQ=R01235
```

Официальный курс USD/RUB с датой действия и номиналом. Формат XML — второй
источник отличается от первого и форматом, и способом получения.

Курс используется как внешний признак, его полезность проверяется при сравнении
моделей. USDT не равен официальному доллару, поэтому пересчёт котировок в рубли
не выполняется. Торги идут ежедневно, курс публикуется не каждый день: в витрину
попадает последний курс с датой не позднее суток `d`, давность записи хранится
отдельным полем.

## Слои хранения

| Слой | Назначение | Таблицы |
|---|---|---|
| `raw` | Данные источников без изменений | `okx_btc_usdt_daily`, `cbr_usd_rub` |
| `clean` | Проверка качества, приведение типов | `okx_btc_usdt_daily`, `cbr_usd_rub` |
| `mart` | Витрина для анализа | `daily_market_mart` |

В слое `raw` вместе с разобранными полями хранятся исходные фрагменты JSON и XML
для прослеживаемости значений до источника.

Журналы: `load_log` — запуски загрузки, `data_quality_log` — результаты проверок
с причинами отклонения записей.

Витрина `daily_market_mart` — одна строка на сутки. Признаки известны на конец
суток `d`, целевые значения взяты из суток `d+1` и хранятся отдельными полями.

## Ограничения

- Объём отражает торги только на OKX.
- Длина ряда позволяет провести временную валидацию, но не гарантирует точность
  прогноза при смене рыночного режима.
- Полезность курса USD/RUB не подтверждена.
- Первая свеча исторического ряда может быть неполной.
- Использование зарубежного источника требует согласования с преподавателем.

## Этапы

| Этап | Содержание | Состояние |
|---|---|---|
| 1 | Постановка задачи, анализ источников, репозиторий | Выполнена |
| 2 | Загрузка в слой `raw`, журнал загрузок | Выполнена |
| 3 | Слои `clean` и `mart`, контроль качества | Выполнена |
| 4 | Дашборды | Предстоит |
| 5 | Прогнозное ядро, валидация моделей | Предстоит |
| 6 | Метаданные, историзация | Предстоит |

Прогноз пока не формируется, точность не измерена.
